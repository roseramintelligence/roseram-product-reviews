## Place data should be tested against ordinary exceptions

A useful sample includes a renamed business, a branch with a similar name and a place that has changed status. Inspect the fields that matter to the application instead of judging the dataset by whether a familiar landmark appears.

## A developer integration needs a clear result contract

Decide how the application uses a place identity and which fields it requires. A displayed search result and a persistent local record may need different handling. Include missing values and ambiguous matches in the test rather than assuming every response is complete.
