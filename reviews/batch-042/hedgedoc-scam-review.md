# HedgeDoc review: features, pricing and buyer considerations

**Last editorial review:** 2026-11-24  
**Category:** Self-hosted collaborative Markdown  
**Method:** Source-led desk review; no hands-on testing is claimed.

HedgeDoc is an open-source, browser-based collaborative Markdown editor designed for self-hosting. Its official overview describes real-time collaboration, note permissions, revisions, diagrams and presentations. It identifies the project’s former CodiMD name while distinguishing another project with that name.

## Editorial verdict

HedgeDoc is a relevant candidate for a team that wants shared Markdown and can operate a server responsibly. Evaluate a meeting note from invitation through export and recovery. Self-hosting changes who is responsible for availability, access and maintenance; it does not remove those responsibilities.

## A shared meeting note is a useful trial

Choose a realistic collaborative task: one person opens the note, another adds a decision and a third reads the result afterward. This tests the complete shared workflow more effectively than typing simultaneously just to watch cursors move.

Decide where the approved record will live after the meeting. A working scratchpad and a durable decision log can have different audiences and review requirements. The software supplies collaboration; the team still defines when the contents are considered final.


## A note link needs understandable permissions

The official overview describes a permission system for notes. Use separate test identities to check the actual reader and editor experience on the chosen instance. A person receiving a link should not need to guess whether they can modify the document or whether others can read it.

Test changing access and returning through an earlier link. Inspect direct access rather than relying only on what navigation controls are visible. This review proposes an application check without claiming Roseram audited HedgeDoc’s authorization implementation.


## Revisions are useful when someone knows how to recover

A shared document can be accidentally overwritten or reorganized in a way that loses useful context. The official site describes revision recovery. Try that process with an expendable note before the first urgent incident.

Keep the intended recovery action specific. Restoring earlier content is not the same operation as changing note permissions or recovering a server. A practical team guide should distinguish those tasks so a contributor does not make a confusing situation worse.


## Self-hosting needs an owner beyond installation day

Installing an editor is only one part of providing a service. Identify who handles updates, backups, access configuration and recovery when the host fails. Record how the team would regain its notes independently of the ordinary web interface.

Compare that operating effort with the needs of the audience and any managed alternatives. Roseram did not deploy HedgeDoc, restore a server or verify a particular instance. This review is based on public documentation and an editorial evaluation of the complete collaboration workflow.


## Features and decision criteria

- Self-hosted browser Markdown editor
- Real-time collaborative editing
- Note permissions and revisions
- Diagram and presentation capabilities

## Pricing considerations

The official overview describes open-source software under AGPL 3.0. Hosting, operations and any support arrangement are separate costs. The public demo is not established as a durable production account.

## Frequently asked questions

### Is HedgeDoc a managed hosting subscription by default?

The project describes a self-hosted editor. A hosted instance and its operating terms need to be evaluated separately.

### Was HedgeDoc previously called CodiMD?

The official page explains that it was renamed to avoid confusion with another project of the same name.

### Should I use the public demo for important permanent notes?

Do not assume that. The project explicitly asks visitors to read the demo’s reliability information.
